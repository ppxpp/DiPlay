## 昼夜模式：保留正式功能，删除哪些测试入口

你已确认真实车机的白天/夜间模式完全跑通。正式流程继续为：

1. 车机系统通知当前白天或夜间状态。
2. DiPlay 接收并保存该状态；通知优先于可能较旧的首次查询结果。
3. 选择车机昼夜模式时，DiPlay 将状态传给 CarPlay，连接建立后也会同步当前值。
4. 已验证的先锋有线连接保持省略特定外观声明的方案，让 iPhone 接受正常的模式切换命令；其他设备沿用上游行为。

已删除：

- 设置页“车机日夜调试悬浮窗”的开关、说明和相关权限提示。
- 悬浮窗本体、启动/刷新调用及其偏好保存接口。
- 仅给悬浮窗使用的原始查询/通知字段及周期查询入口。
- TCP 手动强制白天、强制夜间、重新同步的测试命令。
- 外观声明的临时对照开关及客户端命令。

正常的车机监听、首次状态读取、观察者销毁清理、CarPlay 同步均保留。
其他功能使用的悬浮权限不受影响；自动化回归测试仍用于保护正常功能。

另外修复了开机初始化问题：服务暂时未就绪或监听注册失败时，会有限重试；
注册成功后不会重复注册。连续尝试达到上限后，后续重新打开相关页面可以再试。

## 13 项问题逐项处理

| 编号 | 原问题，用容易理解的方式说明 | 现在的处理 |
| --- | --- | --- |
| F01 | 即使只发“暂停”，旧广播也会先启动 WeCarFlow 的完整播放器 | 删除这条广播及其接口。由已有独立桥接向已登记、已运行的播放器发暂停；不为暂停冷启动原业务 |
| F02 | 正在寻找/连接蓝牙代理时，退出操作可能被几十秒网络等待挡住 | 网络等待移出关闭锁；正在握手的 socket 可以被取消；连接成功发布前再次核对它仍属于本次连接 |
| F03 | CI 声称只构建源码，却仍强制要求私有 CarPlay 认证文件 | 明确增加源码验证模式，CI 使用它；车机包继续强制检查认证素材；同时修正 Gradle 配置缓存兼容问题 |
| F04 | 端口注册被中断后，监听可能已经创建，却没人负责释放 | 中断、超时和失败统一走取消/补偿流程，保留线程中断标记 |
| F05 | 普通队列满时，端口释放请求可能永久丢失 | 释放请求走独立通道，由唯一的网络处理线程执行；旧连接的释放不能碰新连接 |
| F06 | 慢上传、慢导出可以占住调试线程，后续停止/状态命令排不上 | 有界接入且不积压 socket；大文件与控制命令分别限流；增加完整请求时限及阻塞写超时关闭 |
| F07 | 代理快速重启，上一轮线程收尾可能关闭下一轮连接 | 每次启动独立保存 socket、蓝牙、发现服务和计数；旧线程只能清理自己持有的资源 |
| F08 | 蓝牙服务查询完成了，界面却一直显示忙碌 | 成功、失败、拒绝、超时、取消直接结束对应查询；旧超时不能结束新查询，不再靠日志文字驱动状态 |
| F09 | 仪表只收到歌名，却被当成 WeCarFlow 也收到完整播放状态 | 仪表文字与 WeCarFlow 的播放/暂停、进度、缓存分别发布，各自记录成功，各自重试 |
| F10 | 会话状态读取失败时可能误判为空闲；上传期间也可能又开始连接 | 缺字段、错误、超时均拒绝升级；上传前、上传后、安装器启动前复查；升级、连接启动及缓存清理共用互斥规则 |
| F11 | 切后台时，每个播放器可能在界面线程各等 2.5 秒 | 提前准备退场，截图与所有播放器共享 120ms 退出准备 + 80ms 退出宽限；超时仍关闭并追踪解码器；真正 Surface 销毁仍保留释放确认屏障 |
| F12 | 昼夜监听初始化失败一次，同进程以后就不再尝试 | 成功注册与初始化中的状态分开管理，失败有限重试，成功不重复注册 |
| F13 | 进程打开文件很多时，旧 socket 检查方式可能越界并崩溃 | 自研 native 连接检查改用 poll，处理无效描述符和连接错误，保持原来的单线程所有权模型 |

这里的 F11 表示代码中的等待预算，不是整次页面切换或硬件调用的实时上限。
硬件解码器永久卡死时，Java 层无法强行证明它已经停止使用 Surface；因此没有删除最后的释放确认与追踪。

复审另外补上两项边界：缓存清理取得与上传相同的租约，不能删除正在上传的包；
已交给安装器的 APK 留有标记，24 小时内清理命令跳过它，避免安装器还在读文件时被删。

## 代码组织调整

- **正式设备规则独立。** 新增 `PioneerPlaybackPolicy`，正式音频和外观声明读取它，避免为了读取默认值而初始化调试服务的 Handler。音频时钟的现有对照覆盖仍可热切换。
- **调试服务拆职责。** 连接接入/时限由 `PioneerDebugConnections` 管理，上传和校验由 `PioneerDebugUpdater` 管理，升级互斥由 `PioneerDebugUpdateGuard` 管理。
- **界面退场单独管理。** `PioneerSurfaceRetirement` 保存同一次退场的共同起点和截止时间；Activity 只触发准备与确认。
- **设备适配统一收尾。** `DiPlayVehicleIntegration` 用同一个 Binding 持有播放保护和音源恢复，替换控制器时一起释放。
- **两份 WeCarFlow 适配区分身份。** 根目录是当前维护的 WeCarFlow；`DiPlay/vehicle-support/wecarflow` 已标记为旧 QQMusic 基线，不可混用。
- **当前 WeCarFlow 纳入版本控制。** 新建独立本地 Git 仓库，36 个维护文件已加入暂存区，尚未提交、未配置推送。原包、密钥、完整反编译树和 APK 均排除。历史上没有保存的提交无法补回。
- **构建可从固定原包重现。** `baseline.json` 固定原包摘要、apktool/JDK/SDK 工具版本；发布重新解包到 `build/repack/decoded/`，不依赖旧工作树的补丁标记；新增测试基线准备脚本。
- **名字与文档统一。** 中央桥接状态字段由 `mainProcess` 改为 `centralProcess`，明确它不是原播放器主进程；修正文档中过时的“必须卸载”和旧进程说明。

本轮选择按职责提取当前适配代码。上游 Activity 的整体体积及整个 native 文件的全面格式整理仍属于后续维护工作；本轮没有重写已经验证的第三方协议实现。
