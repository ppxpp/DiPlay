# MODE 切换音源后 CarPlay 无声排查记录（2026-10-17 16:44）

当前阶段：已保存故障现场并上传诊断包，尚未完成修复验证。

## 发生了什么

用户反馈：播放 CarPlay 音乐时，用车机 MODE 键切换音源，再回到爱趣听，音乐画面还在播放，车内没有声音。断开重连 CarPlay 可以恢复。

## 本次已经确认的事实

- TCP 调试正常，车机运行 DiPlay Release v92。没有 ADB 连接。
- CarPlay 控制连接和视频正常，歌词与歌曲进度继续变化。
- 16:36:29.372，DiPlay 收到“永久失去音频焦点”的通知。焦点可以理解为车机允许哪个应用使用声音通道。
- 16:36:30，音乐音轨退出，音乐接收线程退出，两个音乐 UDP 端口被注销。UDP 端口是接收 iPhone 音乐数据的入口。
- 此后音乐接收、解码、写入的计数持续为零。故障不只是扬声器音量变小，而是音乐传输链路已经停止。
- 在同一次连接中点击暂停、继续，没有观察到音乐数据重新建立。
- 旧日志会过滤带完整协议内容的记录，因此尚不能断言是谁要求关闭音乐、为何切回后没有恢复；蓝牙输出切换、CarPlay 音频资源归属等仍属待证实方向。

## 已做的调整

诊断用 Debug v93 已构建成功、签名验证通过，并已通过 TCP 完整上传。补充：

1. 音频流何时建立、何时关闭的简要记录。
2. iPhone 通知的声音资源归属，不记录密钥等协议敏感内容。
3. 读取当前车机音源，以及主动切换 FM / 爱趣听的调试入口，用于复现。

这些是定位问题的诊断改动，不能当作已经修复无声问题。v93 安装需要在车机系统安装页确认；最新查询车机仍为 v92。

## 后续验证

1. 安装 v93，打开 DiPlay 并恢复 CarPlay 音乐。
2. 记录正常声音链路，再通过 FM → 爱趣听切换复现；必要时补测物理 MODE 键经过的不同音源。
3. 确定关闭音频的协议通知及当前音源、音频焦点，修复切回后的恢复环节。
4. 在不重新连接 CarPlay 的情况下，反复切换音源验证恢复；确认切到 FM 时不会被 DiPlay 自动抢回。
