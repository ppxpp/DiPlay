# DiPlay next release notes

Changes through DiPlay 0.2.20 are documented in [0.2.20 release notes](RELEASE-NOTES-0.2.20.md). Measured checks are in [VALIDATION.md](VALIDATION.md). Device acceptance and remaining failure families are tracked in [connection reliability validation](CONNECTION_RELIABILITY.md).

## Connection setup and recovery

- When wireless CarPlay cannot start, the CarPlay screen names the reason: "Hotspot network is not ready" when the car hotspot never comes up, or "The iPhone did not connect to CarPlay in time". Once the automatic retries stop, it adds "Automatic retries stopped. Check the connection and retry manually." The screen used to say **Getting CarPlay ready…** between and after retries, as if DiPlay were still connecting ([#809](https://github.com/shihabal3amri/DiPlay/issues/809)). A car hotspot DiPlay cannot use (off, on the other band, or no access to start it) is not retried, and the screen now says so instead of "Connection interrupted. Retrying…". [#824](https://github.com/shihabal3amri/DiPlay/pull/824)
- When the wireless permissions were refused, the CarPlay screen names what is missing: Location, Nearby devices (Bluetooth or nearby Wi‑Fi devices), or, for anything else such as Android 17's local network access, a line to check DiPlay's app permissions. After a refusal the screen used to stay on "Getting CarPlay ready…" ([#290](https://github.com/shihabal3amri/DiPlay/issues/290)). It checks again when DiPlay returns from Android's settings. [#795](https://github.com/shihabal3amri/DiPlay/pull/795)
- On BYD DiLink 1.0 (Android 7.1), the Bluetooth and car hotspot buttons open BYD's own Bluetooth and hotspot screens. The settings app there answers sixty standard settings actions with only "多媒体系统不支持此操作" (this operation is not supported), so the buttons showed that message instead of a settings screen. Where no screen can be found, DiPlay says to open the setting from the car's settings app. Other Android versions are unchanged. [#794](https://github.com/shihabal3amri/DiPlay/pull/794)

- DiPlay warns again that the car hotspot is off when it really is. Since 0.2.20, tapping **Connect** on "Car hotspot is off" makes DiPlay trust the driver over Android's report, for firmware that reports its hotspot off while it is on ([#604](https://github.com/shihabal3amri/DiPlay/issues/604)). A BYD Han EV 2020 (DiLink 2.0) keeps its hotspot switch on but starts the hotspot only when its own hotspot page opens, so every attempt then retried for a minute without a hotspot ([#809](https://github.com/shihabal3amri/DiPlay/issues/809)). When an attempt finds no hotspot and Android still reports it off, DiPlay now drops that choice, and the next attempt says the hotspot is off. [#827](https://github.com/shihabal3amri/DiPlay/pull/827)
- DiPlay no longer closes when it opens CarPlay from BYD's DiYou desktop card (DiLink 5.0). Android refused to start the CarPlay screen in its own task there (`There is no running activity in rootTask`), which has happened since 0.2.12 ([#463](https://github.com/shihabal3amri/DiPlay/issues/463)). DiPlay now opens the screen in a new task instead, and logs a second refusal rather than closing. Pending in-car acceptance. [#827](https://github.com/shihabal3amri/DiPlay/pull/827)

## Display

- **Temporary system bars (5 seconds)** in the CarPlay quick menu (**Display → Fullscreen**), off by default: swiping up with the quick-menu finger count shows the hidden status and navigation bars for five seconds, for example to reach the climate controls, without changing CarPlay's size or reconnecting ([#754](https://github.com/shihabal3amri/DiPlay/issues/754)). Swiping down still opens the quick menu. Some firmware may ignore the request. [#818](https://github.com/shihabal3amri/DiPlay/pull/818)
- **Black rounded corners** in the CarPlay quick menu (**Safe area**) paints the screen corners black, at 12, 24, 36 or 48 dp, so rounded CarPlay corners no longer show the wallpaper colour ([#586](https://github.com/shihabal3amri/DiPlay/issues/586), [#635](https://github.com/shihabal3amri/DiPlay/issues/635)). **iPhone mask (experimental)** asks the iPhone for its own corner mask and draws it, and falls back to 24 dp when the iPhone sends none; it applies at the next connection and is not yet tested with a real iPhone. Off by default. [#811](https://github.com/shihabal3amri/DiPlay/pull/811)

## Audio, calls and Siri

- Music no longer plays seconds behind the iPhone. In 0.2.20 the music clock adjustment ([#788](https://github.com/shihabal3amri/DiPlay/pull/788)) measured only the audio buffered in Android, so on head units where that buffer stays below DiPlay's start level it slowed music to its 1.5 % limit, and the rest piled up undecoded: up to 192 packets, about 4 s, on a DiLink 3.0 ([#806](https://github.com/shihabal3amri/DiPlay/issues/806)) and over USB on a Qualcomm head unit ([#719](https://github.com/shihabal3amri/DiPlay/issues/719)). A track change, pause or skip was heard seconds late. DiPlay now counts the music waiting to be decoded, does not learn the head unit's clock from such a backlog, and skips stale music only when more than 1.5 s stays queued for another 1.5 s. Pending in-car acceptance. [#814](https://github.com/shihabal3amri/DiPlay/pull/814)
- Music that stopped after a call or another app's short interruption comes back when the iPhone starts playing again. Some head units never tell DiPlay that the interruption ended, so DiPlay kept its music muted. It now asks Android for audio focus again when the iPhone starts playing, and only unmutes when Android grants it. Pending in-car acceptance. [#804](https://github.com/shihabal3amri/DiPlay/pull/804)

## Wheel keys

- **Play/pause key on the wheel** (**Settings → Vehicle → Wheel keys**), off by default, makes a spare steering-wheel or keyboard key play and pause CarPlay music, for cars with no play/pause button ([#815](https://github.com/shihabal3amri/DiPlay/issues/815)). Keys that remotes and the car already use (navigation, Home, Back, volume, voice and media keys) cannot be assigned. During a call, or without a CarPlay session, the key does what it did before. [#823](https://github.com/shihabal3amri/DiPlay/pull/823)
- **Double press for Siri** (**Settings → Vehicle → Wheel keys**, with the Siri key assigned), off by default: the assigned Siri key opens Siri only on a double press, and both presses still reach the car, so a key that already does something in the car keeps doing it. Siri opens after the second release and an adjustable delay (300 ms by default), so the car's own assistant can close first; the double-press interval is adjustable too (600 ms by default). It works through the wheel-key service when the car's assistant takes the screen, and through the CarPlay window otherwise. [#813](https://github.com/shihabal3amri/DiPlay/pull/813)

## Diagnostics

- The crash record in the report keeps up to six of DiPlay's own stack frames after the first twelve. A crash inside an Android call filled the first twelve with Android's frames, so the record from [#463](https://github.com/shihabal3amri/DiPlay/issues/463) did not show which DiPlay code made the call. [#827](https://github.com/shihabal3amri/DiPlay/pull/827)
- While DiPlay waits for the iPhone over USB, the report lists the USB devices Android sees, as `vid:pid node`, once and again only when the list changes (`wired iPhone not listed by Android; USB devices=[…]`). `iPhone USB device not present` alone could not tell a port that Android does not see at all, such as a charge-only port, from a cable or iPhone problem ([#763](https://github.com/shihabal3amri/DiPlay/issues/763)). [#830](https://github.com/shihabal3amri/DiPlay/pull/830)
