# 厂商适配接入与上游同步说明

更新：2026-10-13。当前实现首先覆盖已检测到的先锋 Android 7.1.2 固件；其他设备继续采用默认 Android 音频路径。

## 实现边界

厂商实现集中在 `shared/src/main/java/com/shilapi/xcertplay/vehicle/adapters/`；接口在 `vehicle/api/`，会话协调和策略选择在 `vehicle/runtime/`。应用层唯一装配入口为 `common/.../vehicle/DiPlayVehicleIntegration.kt`，保持 `common → shared`，厂商代码不访问 Activity。

本轮已实现：先锋音频策略迁移、连接期间的本机保护客户端、PAL 上下曲直接发送 CarPlay、歌曲信息直接 CEAM 输出候选与固定服务回退。QQ 保护及回退服务的可维护补丁在 `vehicle-support/wecarflow/`，需要另外重打并部署 QQ APK。

真实会话连接后启用保护，暂停、导航和后台不解除；实际断开或 controller 关闭时释放。解绑不自动播放本机音乐。使用连接期间的内存保护开关，旧会话回调通过内部身份与代次过滤。

音量及 MODE 保留系统处理。PAL 监听不独占系统事件，QQ 必须部署保护补丁，才能阻止音量、切歌及音源激活导致的本机播放。没有伴随服务时会明确报告降级并发送一次暂停；不能据此认为严格隔离已实现。

## 上游接入清单

| 文件 | 必须保留的通用接入语义 |
| --- | --- |
| `shared/.../orchestration/CarPlayController.kt` | `vehicleSessionListener` 在真实会话激活/结束及关闭时通知；`activeSessionIdentity()` 返回同一个会话身份，不使用屏幕流 token |
| `common/.../CarPlayMediaKeys.kt` | attach/detach 调用装配入口；原 NowPlaying listener 内追加快照分发，保留原媒体、封面和氛围灯逻辑；已具有厂商音频策略时不额外争夺标准媒体键焦点 |
| `shared/.../media/AndroidMediaSink.kt` | 通过 AudioRouteController 获取流、焦点、独立语音租约与写入策略，不再直接引用 Pioneer；保留原媒体/导航焦点与音频队列处理 |
| `shared/.../media/AudioChannelMapping.kt` | AudioChannel 枚举可被公开的音频策略接口使用 |
| `shared/build.gradle` | 增加本地私有厂商 SDK assets 目录 |
| `shared/src/main/AndroidManifest.xml` | QQ 包可见性声明，以便发现保护服务 |

`VehicleAudioRouting` 仅探测一次已知固件能力；反射、流号 400/401、源号 300、PAL 编码及 CEAM 类名仅存在于具体适配实现。原 `media/PioneerAudioRouting.kt` 已迁移，不能在同步时又恢复一份平行实现。

音频源激活前等待保护最多 1800ms；若没有确认成功，记录降级后保留可出声路径。该等待限制不能替代远端同步 Binder 的总执行时间限制。保护握手和解除运行在独立线程，不占用方控/仪表工作队列或 UI 线程。

## SDK 和 QQ 补丁供应

PAL SDK 属于现有分析输入，不提交二进制到 Git。当前使用 QQ 解包目录的 `assets/wecarflow-pal-classes2.dex`，SHA256：

```text
4683c52f3fdcd996edd07d7fdbe4bf885aa129fb6dab921e93502cd9f130b636
```

在 DiPlay 根目录执行：

```sh
python3 scripts/provision_vehicle_sdk.py /path/to/qqmusic/apktool/qqmusic/assets/wecarflow-pal-classes2.dex
./gradlew :mobile:assembleDebug
```

脚本把 SDK 放到 `.private/vehicle-runtime-assets/vehicle/pal-client.dex`，构建时打入 APK，运行时按内容 hash 放入 code cache，避免复用旧版本 SDK。未供应时 PAL 会报告不可用，不能将普通构建成功视为方控可用。CarPlay 原有私有认证素材供应方式保持原样。

QQ 当前分析目标版本为 `3.10.0.7 / 3100007`，包名 `com.tencent.wecarflow`。补丁脚本需要此版本已解包目录，以及 QQ 项目的两份 `scripts/wecarflow_bridge_src` Java 输入；可通过 `--bridge-src` 显式指定。缺少 bridge 时保护仍可编译，仪表回退明确禁用；方法签名失配时报错，不能直接套用其他 QQ 版本。

```sh
python3 vehicle-support/wecarflow/apply_guard.py \
  --apktool-dir /path/to/qqmusic/apktool/qqmusic
```

脚本生成 QQ 服务、非导出进程状态 provider、25 个精确播放/切歌入口拦截和固定服务回退。按用户要求，不校验调用包名、UID、签名或 owner 凭证，使用连接保护开关。`last-applied.json` 保存授权方式与入口清单。补丁源、脚本和说明保存在 fork，生成的 jar/smali/APK 属于 QQ 构建输入和产物，不能当作 DiPlay 主线代码混入。

具体重打工具与授权规则见 [QQ 本机播放保护补丁](../vehicle-support/wecarflow/README.md)。只替换 DiPlay APK 不会自动让旧 QQ 音乐具备保护能力。

## 仪表能力范围

优先调用 CEAM `setAudioIQTInfo`，当前候选接口只接受歌名、歌手和专辑文字；没有已确认的播放状态或进度参数。返回成功只表明接口接受，不证明实际仪表显示。暂停时保留文字，断开时尝试清除文字；系统覆盖与恢复行为需实测。

CEAM 不可用时，通过受保护的 QQ Binder code 4 向原固定 `UpdateWidgetService` 发布完整快照。native 回调在保护期间保留本机快照但不覆盖远端显示；解除时恢复最后的本机状态，不触发播放。控制命令通过媒体回调 Binder 回到 DiPlay，不在 QQ 内执行切歌。

回退路径使用真实时长、播放态及毫秒进度，已知进度在播放期间按单调时钟延伸并限制在真实时长内，每秒刷新；没有进度时不生成虚构进度。没有队列身份、索引、首尾或封面 URL 时不伪造对应字段。发布失败不标记成功，静态或暂停歌曲仍可重试。

直接 CEAM 路径目前是歌曲文字验证实现；完整播放状态和进度仅在固定服务回退路径中实现，不宣称两条路径能力完全一致。

## 同步上游与快速验证

在同步分支合入上游，优先采用上游的新实现，再恢复清单中的少量调用。不要整段复制旧 AndroidMediaSink 或 CarPlayMediaKeys。没有文本冲突时也应核对真实会话、NowPlaying 和音频策略语义。

本次采用目标 APK 构建和既有音频焦点检查，不运行全量回归。日常同步后的最小检查：

- 目标 APK 构建；未启用/未匹配适配时仍使用默认路径。
- 先锋音乐、导航及断开重连；连接即保护，暂停仍保护，退出后恢复本机方控。
- 音量不唤醒本机歌曲，PAL 上下曲只切 iPhone 一次，本机队列不改变。
- 仪表实际文字、切歌、暂停及断开交接；杀掉 DiPlay 后 QQ 保护能够解除。

当前没有在线车机。本轮构建、Java/d8、smali 编译等结果仅说明代码与产物可生成，以上实机行为尚待部署验证。QQ 的独立广告、预览或动态热修复若绕过已识别的播放入口，本轮不能声明已经覆盖。
